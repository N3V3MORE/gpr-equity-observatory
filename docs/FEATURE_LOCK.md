# Feature Lock

Last updated: 2026-06-26

Status: active on branch `codex/pre-merge-gpr-cleanup`.

The GeoRiskLab + GPR Equity Observatory merge is feature locked after completing
Phases 0 through 9. The project is now in release-hardening mode.

## What Feature Lock Means

No new product, research, data, model, dashboard, or workflow features should be
added on this branch unless the user explicitly unlocks feature work. In short:
new features require an explicit user decision.

The lock protects the current completed scope:

- daily ETF GPR Observatory workflow
- monthly benchmark sample mode
- monthly benchmark real mode
- monthly HAC regressions
- monthly expanding-window forecast comparisons
- Monthly Benchmark dashboard tab
- source manifests and validation contracts
- consolidated documentation and profile packaging

## Allowed While Locked

These changes are allowed without unlocking:

- fix failing tests or CI
- fix bugs that break existing documented behavior
- correct docs that are stale, misleading, or incomplete
- update release notes, handoff notes, screenshots, or PR text
- refresh dashboard screenshots without changing dashboard behavior
- adjust deployment configuration without adding new project behavior
- tighten validation for already implemented data contracts
- remove accidental generated byproducts such as coverage files
- address code-review feedback that preserves current scope

## Not Allowed While Locked

These changes require an explicit user decision to unlock feature work:

- add FRED controls
- add GDELT ingestion or analysis
- add country-specific GPR data
- add new model families or new empirical claims
- add new dashboard tabs or product workflows
- change the daily/monthly interpretation boundary
- publish or commit real local monthly outputs
- commit raw third-party data, credentials, or `config/sources.yml`
- broad refactors that are not required for a bug fix, CI fix, or review item

## Unlock Rule

Only unlock if the user explicitly asks to unlock feature work or selects a
post-lock roadmap item for implementation.

When unlocking:

1. Record the chosen scope in a plan or issue.
2. Prefer a new branch for the new feature.
3. Update this file with the unlock reason.
4. Keep sample/real, daily/monthly, and causal-claim boundaries intact.
5. Re-run the relevant full verification set before claiming completion.

## Release Gate

Before calling this locked branch release-ready, verify:

```powershell
git status -sb
uv run --all-extras ruff check .
uv run --all-extras pytest --cov=gprobs --cov=app --cov-report=term-missing -q
uv run --all-extras python scripts/run_task.py monthly-sample --min-train-months 24
uv run --all-extras python scripts/run_task.py build-daily
```

If dashboard behavior changes, also run a Streamlit smoke test.
